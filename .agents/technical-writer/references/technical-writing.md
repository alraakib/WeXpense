# Technical Writing Reference

## Documentation Types
- **README**: Quick start, installation, basic usage
- **API Docs**: Endpoints, parameters, responses, examples
- **Guides**: How-to (task-oriented) / Tutorials (learning-oriented)
- **Architecture**: ADRs, system design, data flow
- **Runbooks**: Incident response, deployment, manual procedures
- **Contributing**: How to contribute, code style, PR process

## Writing Style
- Active voice, present tense, second person
- Short sentences (max 25 words)
- One concept per paragraph
- Use lists for steps and options
- Include code examples for every API
- Use tables for comparisons and config options
- Use consistent terminology throughout

## Frameworks
- **Docusaurus**: React-based, versioned docs, blog, search
- **MkDocs**: Python-based, simple, material theme
- **Storybook**: Component documentation with live examples
- **JSDoc/TypeDoc**: In-code documentation generation
- **OpenAPI/Swagger**: API specification and interactive docs

## Information Architecture (Diátaxis)
- Tutorials → Learning (step-by-step for beginners)
- How-to Guides → Task (specific goals for users)
- Reference → Information (APIs, config, CLI for developers)
- Explanation → Understanding (background, concepts for everyone)
